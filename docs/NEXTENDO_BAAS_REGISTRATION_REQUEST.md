# NEX — BAAS public-key registration request

Updated: 8 November 2026.

This document describes the request generated by **NEX → Configurar rede → Copiar solicitação de registro BAAS**. It is intended for the official Nextendo developer/support channel. It is not evidence that the key has been registered or accepted.

## NEX identity

- Product: NEX, an Android fork of Eden with native Nextendo integration.
- Android application ID: `com.nex.nx`.
- Public OAuth Client ID: `nxc_yAdR-14bOEq7`.
- OAuth redirect URI: `com.nex.nx://oauth/callback`.
- OAuth model: public client using Authorization Code + PKCE (S256); no client secret.

## Proposed signer

Each installation generates an RSA-2048 key pair inside Android Keystore. The private key is non-exportable and only the public JWK is shared. The public JWK uses:

- `kty=RSA`, `alg=RS256`, `use=sig`;
- `kid` equal to the RFC 7638 thumbprint;
- `n` and `e` from the Android Keystore public key.

NEX proposes to sign its BAAS `id_token` using `SHA256withRSA`. The key is different for each Android installation; this proposal requires Nextendo to confirm that the server supports this model.

## Questions requiring a Nextendo answer

1. May NEX use a separate per-installation RSA-2048 key pair generated and retained in Android Keystore, or must NEX use one application-level key through a trusted signing service?
2. Can the Nextendo BAAS JWKS deployment register and publish independently generated public JWKs from multiple NEX installations? The public `baas-jwks` repository currently shows a server-side `BAAS_SIGNING_KEY` from which its served JWK is derived; it does not document a client registration endpoint.
3. What exact HTTPS `jku` URL and path should NEX put in the JWS header (and payload, if required)? Who operates and updates that JWKS endpoint?
4. What exact BAAS `iss`, `aud`, `sub` mapping (PID, NSA or another identifier), `kid`, `typ`, `hm`, `iat`, `exp` and optional title/version claims must NEX use?
5. Does the game verifier accept an Android Keystore-generated RS256 key for a third-party emulator client?
6. Is a separate NEX app/client attestation signature required? If so, please provide the supported third-party public-client process, headers, canonical input, nonce/timestamp rules and key registration/rotation/revocation policy.
7. What is the approved test procedure for verifying BAAS acceptance in the first supported game, Super Mario Maker 2?

## Security boundary

NEX will not copy DEN's private key, ship a shared private key in the APK, reuse another emulator's session/token, or claim that a copied JWK is registered. The app exports only the public key. The runtime remains fail-closed until the exact key is served by the approved HTTPS JWKS endpoint and Nextendo confirms the remaining claim and attestation contract.

A successful JWKS match proves that the public key is available at the configured URL. It does not, by itself, prove that Nextendo accepts a BAAS token or that game multiplayer works.
